# Task2：按图索骥：SDD的核心思想

承接Task1对Vibe Coding问题的认知。Task1认识了即兴编码Vibe Coding带来的各类工程问题，SDD(规范驱动开发)是面向AI辅助时代的软件开发方法论。  
SDD主张AI辅助开发场景下，工程师核心产出是结构化规范文档；代码属于AI依据规范产出的衍生物。规范可版本控制、可审查、可追溯，作为项目的唯一真相来源(Single Source of Truth)。

## 一、AI 辅助开发项目的规模化陷阱

很多 AI 辅助开发的项目，原型阶段运行正常，但随着功能增加，项目逐步走向失控、难以迭代，最终烂尾。并不是 AI 生成的代码不能跑，而是**Vibe Coding 模式自带的缺陷会随着项目规模放大，把小问题变成致命工程债务**。

典型现象：

1. 刚开发时迭代速度极快，简单功能短时间就可以完成；
2. 当模块变多、需要新增业务、修改旧逻辑，修改一处就会引发多处隐性 bug；
3. 没有留存设计决策，只保留 AI 聊天记录；会话一旦丢失，完全说不清当初表结构、接口为什么这么设计；
4. 代码可以运行，但不敢重构、不敢大规模修改，只能不停打补丁；
5. 到后期维护成本远高于重新开发，项目陷入停滞。

> 💡我的理解：这一点对自学者非常有警示意义。我在做项目的时候，小模块开发体验很好，但只要开始跨模块迭代，就会遇到这类隐患。很多Demo，只能跑通演示，无法继续迭代扩展。企业很看重项目 “可维护、可迭代”，而不是仅仅 “能运行”。Vibe Coding 可以快速产出 Demo，但很难支撑一个可以持续演进的后端项目。

## 二、复盘三种主流软件开发范式：瀑布、敏捷、Vibe Coding，看清各自优势与痛点

### 1. 瀑布模型

核心特征：线性阶段，需求分析→设计→编码→测试→上线；**前期完整定义全部需求与文档，之后再编码**，需求变更成本很高。

- ✅优势：文档完整、决策可追溯；适合需求固定、变更少的项目。
- ❌劣势：响应变化能力差，现实业务需求经常发生变动，完全照搬瀑布会造成大量浪费。

> 💡我的理解：瀑布的思想：**文档先行**，这个思路被 SDD 继承，但 SDD 没有照搬瀑布 “需求写完就不能改动” 的缺点。

### 2. 敏捷开发

核心特征：拥抱需求变化，短迭代增量交付；弱化重型前置文档，更看重人和沟通、可运行的软件。

- ✅优势：灵活，快速响应业务变化，是过去十几年互联网行业主流范式。
- ❌劣势：高度依赖团队口头沟通、会议；当引入 AI 编程之后，缺少书面制品，沟通全部转移到 AI 对话窗口，敏捷 “轻文档” 容易直接滑向零文档的 Vibe Coding。

> 💡在我软考备考中，敏捷也是考试重点。敏捷说的是**少写无用的静态文档，不是完全不写文档。**

### 3. Vibe Coding（AI 即兴编码范式）

核心特征：依靠自然语言对话驱动 AI 生成代码，需求、架构、决策全部保存在聊天会话。

- ✅优势：原型开发速度快，适合一次性小脚本、概念验证 Demo。
- ❌劣势：需求蒸发、上下文漂移、不可审查、不可复现、不可维护，规模扩大之后项目极易烂尾。

> 💡三者的演变给我的启发：瀑布太重，敏捷容易被 AI 带偏走向无文档，Vibe Coding 只能用于极小 Demo。AI 时代需要一套新范式，也就是 SDD 规范驱动开发。

## 三、SDD 规范驱动开发，不是回归瀑布

很多人会产生误区：SDD 强调先写规范文档再写代码，是不是等于回到老旧的瀑布模型？答案是否定的。

| 对比维度   | 瀑布模型             | SDD 规范驱动开发                  |
| ------ | ---------------- | --------------------------- |
| 文档性质   | 一次性静态文档，前期写完很少修改 | **可迭代的规范**，需求变化优先修改规范文档     |
| 变更处理   | 变更成本极高，拒绝后期改动需求  | 需求发生变化，优先更新 spec 规范，再驱动代码变更 |
| 文档产出目的 | 交付归档，给人阅读        | 作为人与 AI 共同遵守的契约，直接驱动代码生成    |
| 迭代模式   | 整体一次性交付          | 增量迭代，每一轮迭代同步更新规范 + 代码       |

> 💡瀑布：文档写完就冻结；SDD：**规范和代码一起迭代，规范是源代码的一部分，纳入版本管理（Git）**。放到我的项目中：新增、修改业务，不是直接改代码，而是先修改`proposal.md`、`design.md`，再修改代码。规范和代码一起提交 Git，完整记录每一次业务变更。这一点是 SDD 和瀑布最本质区别

## 四、Task2 学习总结

本次学习梳理了瀑布、敏捷、Vibe Coding 三种范式的优缺点，厘清一个关键误区：SDD 不是复古回到瀑布模型。同时重新解读敏捷宣言，分清 “拒绝冗余文档” 和 “完全不写规范” 之间巨大的鸿沟。

AI 时代要区分两类文档：

- 无用的静态归档文档：写完不再维护，和代码不同步，这类文档敏捷理念下本就不提倡；
- **可执行、可迭代的规范文档（Spec）**：作为 AI 生成代码的输入，业务变更同步更新，这一类文档具备实际工程价值，必须保留。
